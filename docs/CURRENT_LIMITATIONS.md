# 当前限制（V2）

- M3已合成测试22种历史typed消息、可见簿/元数据、可选时间与E/C/P Broken关联及离线检查入口；第五批增加单遍原始源SHA-256和可选gzip完整性，默认关闭zlib依赖。旧默认API仍不启用关联，CLI声明不验证权利，摘要也不认证来源；Q Broken、完整时段/官方tape/账户、市场数据新鲜度、真实授权样本、独立参考与性能未验收。`COMPLETE`只表示配置profile处理完成，不是M3或真实会话验收，见[第五批说明](M3_ITCH_INPUT_INTEGRITY.md)。
- 文件hash针对实际读到的原始流，不提供并发修改时的原子文件快照；expected hash可选且须从独立可信渠道取得，CRC不是安全认证。gzip晚到错误会使前缀簿STALE，不回滚或自动恢复；限额不是总堆/时间预算。本机ASan仅插桩C++封装，链接的zlib Release静态库本身未插桩。
- 简化二进制 Feed 已接入Journal接受后的公开投影、有界整批队列及独立本地簿，但不是交易所协议；仅支持空基线、冻结注册表的单写者进程内会话，无网络、重传、公开序号崩溃续接或外部快照服务，详见[M2闭环](M2_PUBLIC_FEED.md)。
- 新公开链路的字节预算仅约束排队/消费中的wire缓冲，不是总堆上限；映射、deque、Decoder仍会分配。队列满或消费失败终止会话并使本地簿STALE；Journal接受后的失败不回滚撮合，不支持对部分消费批次自动重试。成功入队不等于下游已应用或磁盘持久化。
- `benchmarks/v2_perf.cpp`的历史`full_v2`未启用新公开行情链路。现有3个合成工程场景保留消费完成分位数和wire高水位；2026-11-24另有独立companion的3进程成功C++ new调用/请求字节计数，但仅调用线程、不含worker/malloc/总堆/峰值，不与延迟运行混合。逐层成本、受控/真实数据仍缺失，不是M5正式验收，也不能沿用旧纳秒成绩，见[BENCHMARK](BENCHMARK.md)与[分配边界](PUBLIC_FEED_ALLOCATIONS.md)。
- 数据仅包括合成CSV、项目撮合产生的模拟订单事件及自行构造的ITCH测试帧；尚无通过门禁的外部历史订单级验证集。M3保持股票范围，已计划优先选择Nasdaq 2020-01-30原始ITCH样本但未下载；公开下载不等于允许本地研究、再分发或提交云端AI，仍须分别确认使用条件，不以加密数据替代。
- 风控状态是单账户教学模型，持仓和参考价由外围注入；没有账户层级、PnL、保证金或组合 Greeks。
- PreTradeRisk是可选的上游教学包装器，可被直接TradingEngine调用绕过；不是交易所撮合核心，也不提供成交到持仓/资金的自动完整核算。
- Monitor每次事件更新及snapshot均有mutex；延迟仅存样本数、总量和最大值，没有运行时分位数直方图。其处理计时不覆盖Journal整组提交及公开发布/消费完成，不能代表完整端到端延迟。
- 风控的价格偏离/仓位已精确化并检查累计量溢出，但金额/敞口仍用浮点，金额边界舍入/累计残差及NaN配置校验尚未整体解决；风险重绑不解除Engine FAILED，见[M1第六批](M1_BATCH_06.md)。
- Event Dispatcher 与MarketManager路由/撮合保持同一调用线程；多品种独立簿和异步日志线程不等于按品种并行。没有 UDP、NUMA、多线程撮合或跨进程总线；分片/跨线程交接须等待性能与顺序/恢复契约评审，不预先堆CAS。
- AsyncLogger健康是流/worker状态，不证明dropped=0或持久化；正常stop需生产者静止、单控制者，未提供并发stop等待协议。真实磁盘故障、owned-close注入及诊断payload截断/转义未整体解决，见[M1第九批](M1_BATCH_09.md)。
- Audit冷导出会报告写入/flush/close错误，但filename入口仍为同步文本模式trunc输出，失败可能留下部分文件；字段转义、格式规范化、内存容量及原子/断电保证未实现，实际close失败未注入，见[M1第十批](M1_BATCH_10.md)。
- 订单池已检查重复/外来归还并禁止拷贝，但不识别复用后旧裸指针的代际，也不验证FIFO/索引摘链；其他池规则不因此自动获得同样保证。新增检查的性能无退化尚未验收，见[M1第七批](M1_BATCH_07.md)。
- 单条命令仍使用临时事件vector，V2已预留并限制批次容量，Sink拒收后保留后缀并阻断新命令；map档位等仍可分配，未证明整个核心完全零分配。outbox仅进程内有效，不跨崩溃保留。
- 新价格map分配失败已定点验证并清理未挂簿订单，但不回滚先前成交，异常后仍FAILED；不代表所有分配点/真实系统OOM均已验证。独立故障程序的new/delete替换还限制了自身部分ASan诊断，见[M1第五批](M1_BATCH_05.md)。
- Journal已有v2完整组与标准接线的进程内预留/接受，旧CSV/attach保留兼容；仍无CRC、fsync/durable水位、复制或高可用，不能称生产级WAL。记录槽预算不是总堆字节配额，磁盘满/掉电未实际注入。
- 多品种快照现拒绝generation复用并保留占位/孤儿文件，没有自动GC或磁盘预算。重试不能伪造Journal截点；提交后刷新异常也不保证回滚。快照截点与durable prefix绑定、强杀/断电及并发保存仍无完整保证，见[M1第八批](M1_BATCH_08.md)。
- CI 文件只有在 GitHub runner 实际执行后才构成流水线证据；Gitee 不会自动运行 GitHub Actions。
- 2026-11-23代码提交`6183893`的Linux Release OFF/ON及ASan+UBSan OFF/ON均43/43，ON已实际执行gzip正向测试；异步TSan子集4/4、Benchmark smoke通过，手动10M差分跳过。系统zlib本体未插桩，后续纯文档归档不是新的源码CI。此前`05f003b`默认OFF结果仍独立保留，见[第六批](M3_CI_AND_TEST_ISOLATION.md)与[VALIDATION](VALIDATION.md)。这些结果不覆盖强杀/断电、完整核心并发或新公开链路正式性能。
- 历史 26.7 ns 仅代表旧提交的窄热点微基准，不代表当前 V2 端到端延迟。
